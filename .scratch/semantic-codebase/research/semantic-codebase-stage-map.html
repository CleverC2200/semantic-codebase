02 · Stage references

每个阶段重点参考什么

“参考”不等于“已安装”。每项都标明采用方式和边界，避免原型被外部项目的数据模型或副作用反向绑架。

P0

Benchmark

待实现 runner

判断结构化代码工具是否真的比直接读文件更快、更准、更省上下文。

  • CodeGraph 对照 / 借鉴同题 Baseline 对照、CLI/MCP 可测表面、失败原因收据。
  • RepoBench / SWE-bench 方法参考题目分层、Gold 隔离、容器化和回归评价方法。
  • Codebase Memory 暂缓只作市场观察；不安装 daemon，不采用外部 benchmark 声明。
阶段产物：冻结语料、Baseline/V0.1 同题评测和逐次运行收据。
P1

Definition Registry

Slice 1 已落地

识别 TS/Python 中可定位、可重建并绑定 Evidence 的定义。

  • Tree-sitter 直接复用逐文件 CST、声明候选、源码范围和确定性语法证据。
  • SCIP / scip-typescript 后置 Adapter编译器级 Definition/Reference/Relationship 富集；失败不阻塞 core。
  • Kythe / Unison / CodeGraph 借鉴设计身份与名称分离、Anchor/Evidence、抽取与解析分阶段。
阶段产物：五类 Definition、位置、内容摘要、Evidence 与 Coverage。
P2

Structural Code Graph

GraphStore 基础已落地

把定义组织成可追溯的包含、导入、引用、调用、继承和实现关系。

  • CodeGraph 重点读源码SQLite、文件 hash 增量、抽取后解析、双向邻接和有界查询。
  • Infigraph / Kythe 借鉴设计窄 GraphBackend；Relation 与多个 Evidence 分离。
  • Tree-sitter + SCIP 直接复用Adapter语法关系基线 + 经 Snapshot 校验的可选语义关系。
阶段产物：不可变 Snapshot、自有 SQLite GraphStore、增量等价与六类有界查询。
P3

Context Engine

等待真实瓶颈

针对具体任务和 Token 预算，选择、排序、裁剪并解释上下文。

  • Aider repo-map 首要参考全仓符号概览、依赖排序和固定 Token 预算。
  • RepoGraph / LocAgent 借鉴设计定义/引用子图、关键词到实体、有界邻域和证据源码。
  • GitNexus 隔离参考只借 maxTokens、allowlist、stale-index 边界；许可明确前不接入。
阶段产物：同一 Snapshot/Recipe/预算可复现、可解释、可截断的 ContextPackage。
P4

Behavior Graph

按问题触发

仅在 P2 无法回答时，分析值、控制和污点如何在程序中传播。

  • Joern / CPG Adapter spikeAST、Call Graph、CFG、控制依赖、到达定义和 PDG 分层。
  • CodeQL 对比 spikesource/sink/barrier、局部优先和受限全局数据流。
  • Semgrep CE Finding Adapter确定、离线、单文件规则；不能冒充跨文件行为图。
阶段产物：独立 Behavior namespace、CFG/数据流/污点路径、Coverage 和 Diagnostic。
P5

Software Knowledge Graph

计划阶段

统一代码、配置、文档和运行观测，同时保留来源、确定性与保留策略。

  • PROV-O 词汇参考Entity / Activity / Agent 与 generated / used / derived 来源边界。
  • Graphify 受限 Adapter异构本地工件、确定性抽取与 EXTRACTED/INFERRED 分层。
  • OpenTelemetry 后置 AdapterResource、Span、时间窗和 observed 运行证据；不证明完整行为。
阶段产物：自有 Fact + Evidence + AdapterRun + Snapshot 事实核。
P6

Capability Graph

计划阶段

识别组件共同实现的产品/业务能力，并让每个候选都能解释和人工裁决。

  • Backstage Catalog Adapter + 借鉴Domain → System → Component/API/Resource、声明式 YAML 与 freshness。
  • Graphify 候选生成聚类与报告只产生 CapabilityCandidate，必须回链 P5 Evidence。
  • GitNexus 暂不接入只借影响、聚类、流程的查询分面；许可证不清时不复制。
阶段产物：Capability Candidate 及接受、修改、合并、拒绝的人工决策流。
P7

Cognitive Compiler

展示器已就绪

按受众、任务和预算，把已接受事实编译为可理解、可追溯的故事与地图。

  • Archify 构建期展示器消费已验证 typed JSON，validate/deliver 自包含架构与流程 HTML。
  • Structurizr 借鉴设计模型与视图分离、C4 分辨率；不作为默认运行时依赖。
  • Understand Anything 体验参考探索、搜索、提问和渐进披露；模型摘要不进入事实管线。
阶段产物：Evidence-linked Projection/Story、架构图和自包含 HTML。

04 · Prototype landing

现在真正要做什么

当前代码已经完成 Slice 1 的 Definition/Evidence 与 SQLite Snapshot 基础，但还不是完整的 Structural Graph。

下一条主线：继续完成 P2

  1. 补齐 Relation 抽取、解析与 Evidence 绑定。
  2. 实现增量同步与“增量结果等价于全量重建”。
  3. 完成六种有界查询，并让 CLI 与 MCP 共用严格 JSON 契约。
  4. 在冻结 CodeGraph 自举提交上形成首个真实项目演示。
  5. 运行轻量 Benchmark 后，再决定是否进入 P3。

当前明确不做

  • 不部署本地模型或后台 daemon。
  • 不提前引入图数据库、向量库或全局 3D UI。
  • 不把 SCIP、Joern、Graphify 等计划项写成已落地。
  • 不让 LLM 摘要或聚类成为权威事实。
  • 不把私有源码发送到外部评测路径。
