# 源码阅读工作台视觉与交互审计

范围：本地 Zod 13 文件预览，目录、文件函数列表、函数详情、主线步骤和源码阅读。先审计再集中修复，不调整语义事实或发布回执。

## 结论

产品结构可用，主要缺陷集中于布局和导航状态。原版列表与详情重复呈现完整参数表；中等宽度的侧栏直接覆盖正文；函数跳转后重绘丢失焦点。已经完成下列定向修复。

内部设计检查评分（0–4，仅为本轮工程判断，不是 WCAG 认证或用户满意度）：

| 维度 | 修改前 | 修改后 | 依据与边界 |
|---|---:|---:|---|
| 可访问性 | 2 | 3 | 恢复目标焦点，Esc 返回，状态提示；未做完整读屏测试 |
| 性能 | 2 | 3 | 按主体预分组 facts，减少每次查询重复全量过滤；未跑长期性能基准 |
| 响应式 | 2 | 3 | 1440、1024、390 宽度现场检查，无页面级横向溢出 |
| 主题一致性 | 2 | 2 | 浅色与绿色关联语言保持一致；仍有局部色值，未实现深色主题 |
| 实现完整性 | 2 | 3 | 阅读、搜索、定位、返回形成闭环；主线仍为静态候选 |
| 合计 | 10/20 | 14/20 | 从需要明显改进到可继续试用 |

## 发现与处理

- P1 / 响应式：原 1024 宽度详情固定覆盖正文。修改后宽屏三栏；681–1180 宽度详情替代中间阅读区、保留目录；手机详情使用独立阅读区。无重叠背景仍可点击的问题。
- P1 / 信息层级：列表重复完整参数表与解释，造成长距离滚动。改为功能、输入、输出摘要，完整表和示例保留于右侧；文件内增加函数选择器。
- P1 / 可访问性：原函数点击后 document.activeElement 为 BODY。重绘后将焦点交给详情标题；Esc 关闭后回到对应函数，增加 role=status。
- P1 / 导航：切换文件沿用旧滚动位置，容易错过文件职责。换文件或模式回顶部；历史返回恢复阅读、目录和详情滚动位置。
- P2 / 定位：搜索只能过滤文件，用户仍需查找函数。加入最多 20 条直接函数结果、匹配总数和清空操作；快速定位同步选中函数。
- P2 / 排版：四层固定目录前缀挤压文件名。保留完整路径说明，将固定前缀压成面包屑，目录从 helpers 等实际分组展开。
- P2 / 源码：长类型和代码迫使左右滚动。新增默认换行以及显式切换按钮；保留行号。
- P2 / 操作：详情缺少快捷导航。固定解释、源码、关联入口；阅读模式导航固定在各自滚动区域顶部。

位置：scripts/semantic-reader-client.js、scripts/semantic-reader.css、scripts/semantic-preview-explorer.mjs。

## 现场验证

- 宽屏：函数选择器 → isDirty → 详情标题获得焦点；状态提示为已打开 isDirty；没有页面级横向溢出。
- 详情：源码导航定位到源码段；Esc 收起详情后焦点回到 isDirty。
- 搜索：isDirty 返回 1 个可直接点击函数结果，包含所属文件。
- 1024 宽度：目录 232px；详情使用剩余 792px，正文隐藏，不被覆盖。
- 手机：目录可打开和关闭；external.ts 无函数状态可读；换文件 reading.scrollTop 为 0；无页面级横向溢出。
- 定向数据测试 5/5，类型检查与 git diff --check 通过。机械设计扫描没有发现项；不能替代视觉或完整无障碍验收。

## 保留的边界

## 第二轮审计建议落实（用户已授权全部修改）

1. 函数搜索：Esc、Tab 和点击外部取消时恢复已选函数名；重新点击可展开；已选项与键盘焦点分别标记。
2. 主线入口：233 项混合下拉改为 3 个带用途说明的候选；其余 230 个函数内流程放在可展开的搜索区域，显示匹配数并限制首屏结果为 30 项。
3. 搜索范围：左侧明确为全部分析文件与函数，展示文件和函数匹配计数；顶部明确当前文件函数及总数，展开后显示匹配数。
4. 详情导航：固定当前函数名，解释、源码、关联随阅读更新。点击导航在滚动受底部空间限制时仍保留所选栏目；手动滚动重新按可见位置判断。
5. 文案：历史按钮改为“后退”；关闭详情按钮改为“关闭详情 · Esc”。
6. 流程步骤：优先展示处理动作、条件与关联函数；节点编号和原始语句收进步骤证据；控制边使用“继续”“条件成立”等中文含义，保留原始证据。
7. 样式与体积：合并相同作用域下重复选择器，移除旧覆盖式响应布局及废弃选择器。阅读数据不再嵌入界面未消费的 call_data_flow、entrypoint；原始 overlay、证据与验收资料保留。HTML 从 7,155,323 字节降至约 5.54 MB，减少约 22.5%。未据此宣称运行速度提升。

本轮验证：搜索无匹配后取消、重新打开及已选标记正常；其他流程搜索 mergeObjectAsync 得到 1 项；源码与关联按钮高亮正确。实际键盘选择 isAsync 前后 reading.scrollTop 均为 1911；自动化 locator 按键自身会重新定位输入框，因此该检查改用原生按键。1280 桌面与 390 窄屏已查看；390 下详情宽度为 390，正文按预期隐藏，无页面级横向溢出。定向测试 5/5、类型检查通过；本轮仅刷新既有快照 HTML，未重新索引、执行被索引应用或调用模型。


## 用户反馈修正：稳定目录与函数路线图

用户指出，流程切换后目录中只剩关联函数，层级缩进也不足。这一轮以完整目录作为稳定导航，移除“只看流程相关文件”过滤入口；每个文件可独立展开完整函数列表，文件夹子级和函数子级使用缩进与层级线，文件夹、文件、函数具有不同标识。切换流程和步骤只更新关联高亮，不再改写目录内容或自动展开目录。主动点击函数可展开其所在文件以定位。

中间新增函数调用路线图，显示起点、直接调用目标和箭头；节点可打开函数详情，调用位置可展开证据。步骤选择高亮该步骤调用，其他分支保持可见。未解析调用使用虚线节点；过长表达式以中性短标题展示，完整表达式仍在证据里。“主线阅读”改称“函数流程”；流程选择收在“切换函数流程”中，让路线图成为首要内容。

现场检查：从错误收集切换到对象合并，目录 13 个文件、328 个函数及展开状态完全一致；对象合并图显示 mergeObjectSync → ParseStatus.dirty，共 2 处调用。选择入口步骤后，该分支降为非高亮但节点不消失，目录数量不变。错误收集保留 makeIssue、getErrorMap 两个已解析目标及两个未解析调用。390px 视口路线图改为纵向，目录层级可读，无页面级横向溢出。路线图仍是一层静态直接调用关系，不冒充完整业务链或运行轨迹。
